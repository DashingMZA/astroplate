# Installation

## Prerequisites

| Requirement | Version |
| --- | --- |
| Node.js | 24+ |
| pnpm | 12.19.0 (the repo pins this in `package.json` under `packageManager`) |

Check yours:

```bash
node --version
pnpm --version
```

If pnpm is not installed, enable it via Corepack (ships with Node):

```bash
corepack enable
corepack prepare pnpm@12.19.0 --activate
```

No other accounts, API keys, or secrets are needed. The static build
works with zero environment variables. Optional integrations
(Google Tag Manager, Disqus) are disabled by default; see
[CONFIGURATION.md](CONFIGURATION.md).

## Clone

```bash
git clone https://github.com/DashingMZA/astroplate.git
cd astroplate
```

## Install

```bash
pnpm install --frozen-lockfile
```

This installs dependencies exactly as recorded in `pnpm-lock.yaml`.
Do not use `npm install` — the repo is pnpm-based and the lockfile is
pnpm-only.

## Develop

```bash
pnpm dev
```

This runs, concurrently:

1. `node scripts/themeGenerator.js --watch` — regenerates
   `src/styles/generated-theme.css` from `src/config/theme.json` whenever
   the theme changes.
2. `node scripts/jsonGenerator.js` — builds the `.json/` search index
   (`posts.json`, `search.json`) from `src/content/`.
3. `astro dev` — the dev server.

Open the printed local URL (Astro defaults to `http://localhost:4321`).

## Build

```bash
pnpm build
```

This runs, in order:

1. `node scripts/themeGenerator.js`
2. `node scripts/jsonGenerator.js`
3. `astro build` — static output in `dist/` (30 pages)
4. `node scripts/llmsGenerator.js` — generates `llms.txt`,
   `llms-full.txt`, and per-page `.md` files from the built HTML

## Preview the production build

```bash
pnpm preview
```

Serves `dist/` locally. Always preview after a build before deploying.

## Type-check, lint, and test

```bash
pnpm check    # astro check — 0 errors expected
pnpm lint     # eslint — 0 errors expected
pnpm test     # node:test — all tests expected to pass
pnpm format   # prettier -w ./src
```

Individual generators can also be run on their own:

```bash
pnpm generate-json   # search index only
pnpm generate-llms   # LLM docs only (requires an existing dist/)
```

## Troubleshooting

### `pnpm install` fails with EPERM / chown / fchown errors (sandbox only)

In some sandboxed environments the filesystem mount forbids `chown`,
so `pnpm install` can fail while writing lockfiles with an `EPERM`
`chown`/`fchown` error. **This is a sandbox quirk, not expected
behaviour on a normal machine.** Workarounds that worked in that
environment:

```bash
# Regenerate a missing lockfile without a full install:
pnpm install --lockfile-only

# If the build's pre-check step trips the same error, run the build
# steps directly instead of `pnpm build`:
node scripts/themeGenerator.js && node scripts/jsonGenerator.js && npx astro build
```

On a normal machine, plain `pnpm install --frozen-lockfile` and
`pnpm build` work as documented above.

### `pnpm build` fails: “dist/ folder does not exist” (llms step)

`scripts/llmsGenerator.js` reads the built output, so it needs a
successful `astro build` first. If you ran the build steps manually
(see above), make sure `astro build` completed before running
`pnpm generate-llms`.

### Port already in use

If `pnpm dev` reports the port is taken, another Astro/dev server is
already running. Stop it, or pass a different port:

```bash
pnpm dev -- --port 4322
```

### Node version mismatch

The repo targets Node 24+. On older Node versions, Astro 7 / Vite 8
may fail to start or build. Upgrade Node rather than downgrading
dependencies.

> Note: the `Dockerfile` in this repo uses a `node:24-alpine` base
> image, matching the Node 24+ local-dev requirement above, and pins
> pnpm to the exact version in `package.json` (12.19.0). The Docker
> path has not been verified against the current dependency set — no
> Docker daemon is available in the sandbox — so treat it as untested
> until someone builds and runs it. See [DEPLOYMENT.md](DEPLOYMENT.md).

### Stale generated files

If search results or theme colours look out of date after editing
content or `theme.json`, regenerate explicitly:

```bash
pnpm generate-json
# theme CSS is regenerated by the dev watcher; for a one-off run:
node scripts/themeGenerator.js
```

Then restart the dev server.
